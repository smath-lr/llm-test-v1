
## 1. 测试背景

被测对象：自己封装的 Python LLM API 客户端，主要入口为 `chat()`，通过 OpenAI SDK 兼容接口调用 DeepSeek API。

测试目的：验证 LLM API 客户端的调用能力、输入处理、异常处理及响应解析是否符合预期。

## 2. 测试目标

1. **输入处理**：Prompt 内容非空、长度符合 1～200 个字符的限制，且能够正确转换为 API 所需的 `messages` 格式。
    
2. **请求调用**：单轮和多轮对话请求参数传递符合预期，包括 `messages`、`api_key`、`base_url`、`timeout`、`model`、`temperature`、`max_tokens` 等。
    
3. **异常处理**：请求超时、连接异常、400 等异常响应按照预期的异常处理及重试规则执行。
    
4. **响应解析**：正常场景能够正确提取响应文本；缺少必要字段、空 `choices` 等异常响应能够正确处理。
    
5. **多轮对话**：验证 `messages` 列表中的消息角色、顺序和内容能够按照预期传递，确保客户端正确支持多轮对话请求。
    
6. **流式输出**：未来扩展，暂不纳入当前验收目标。
    

## 3. 测试范围

**当前测试范围：**

- `chat()` 接口
    
- Prompt 输入校验
    
- 请求参数传递
    
- 重试机制
    
- 响应解析
    
- 单轮和多轮对话
    

**未来扩展：**

- 流式输出等尚未实现的功能，暂不纳入当前退出标准。
    
- 模型安全评估，包括 Prompt 注入、越狱及有害内容响应评估。
    

**不测试：**

- 图片、文档 API 调用
    
- DeepSeek 以外的其他模型适配
    

## 4. 测试策略

### （1）测试执行方式

1. **Mock 测试**：验证输入处理、请求参数传递、异常处理、重试规则及响应解析。
    
2. **真实 API 冒烟测试**：验证客户端与 DeepSeek 服务的基本连通性及实际调用结果。
    

### （2）测试设计技术

1. **等价类、边界值**：验证 Prompt 和请求参数的有效、无效输入及边界情况。
    
2. **异常测试**：验证请求超时、连接失败、参数错误等异常场景。
    
3. **场景测试**：验证多轮对话、重试后恢复、重试耗尽等完整流程。

## 6. 测试数据

1. **正常 Prompt**：有效的普通文本，验证能够正常发送请求并提取回复。
    
2. **空 Prompt**：验证空字符串等无效输入是否按照当前输入校验规则接受或拒绝。
    
3. **超长 Prompt**：设计四种长度场景：
    
    - 正常长度；
        
    - 接近允许长度边界；
        
    - 达到允许长度边界；
        
    - 超过允许长度边界。
        
    
    验证客户端是否按照实际长度限制进行处理。
    
4. **多轮对话数据**：包含不同消息角色、顺序及内容的数据，验证消息结构和内容是否正确传递。
    
5. **异常模拟数据**：模拟不同异常类型，验证对应的异常处理、重试次数及最终结果。
    
6. **模型安全行为观察数据（非当前核心验收范围）**：使用有害问题测试数据，观察模型是否按照预期拒绝回答。该场景用于探索模型安全行为，不作为当前客户端功能是否通过的判定依据。
    

## 7. 进入和退出标准

### 进入标准

- 测试环境能够正常运行。
    
- 测试账号及 API 配置准备完成。
    
- 测试用例及测试数据准备完成。
    

### 退出标准

1. **核心场景**：当前测试范围内的核心测试用例全部执行。
    
2. **测试结果**：P0 核心用例全部通过。
    
3. **缺陷**：无未解决的阻断性问题。
    
4. **异常**：失败用例均有分析记录，不存在未解释的失败。
    
5. **报告**：具有完整的测试执行结果和测试报告。
    

### P0 核心用例

- 正常请求能够成功调用并返回文本。
    
- 正常 Prompt 能够正确转换为 messages 并传递。
    
- 无效 Prompt 能够按照校验规则抛出异常，并停止 API 请求。
    
- 多轮对话 messages 的角色、顺序和内容能够正确传递。
    
- 请求超时和连接异常按照预期执行重试。
    
- 不需要重试的异常不会发生重试。
    
- 重试耗尽后能够正确抛出异常。
    
- 空响应或缺少必要字段时能够正确处理。
    

## 8. 风险与限制

1. **真实 API 费用**：真实 API 调用会产生 Token 消耗和费用，需要控制测试次数及测试数据规模。
    
2. **Mock 测试局限**：Mock 只能验证客户端自身的处理逻辑，不能完全验证服务端的实际执行情况。
    
3. **网络与服务限制**：网络不稳定、429 限流、账号额度不足等可能影响真实 API 测试结果。
    
4. **模型输出不确定性**：相同 Prompt 可能产生不同回答，真实 API 测试不宜对非确定性内容设置过于严格的固定文本断言。
    
5. **服务商模型变化**：模型升级、接口变更可能影响测试结果，需要关注服务商 API 变化。
    
6. **重试机制风险**：重试可能产生重复调用和额外 Token 消耗，需要关注重复执行、幂等性及费用风险。
