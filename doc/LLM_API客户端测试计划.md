# LLM API 客户端测试计划

被测对象：自己封装的 Python LLM API 客户端，主要入口为 `chat()`。

## 1. 测试目标

1. **输入处理**：合法输入能够通过，非法输入在发请求前被拒绝。
2. **请求调用**：单轮和多轮对话的请求参数按预期传递。
3. **异常处理**：该重试的按规则重试，不该重试的直接失败。
4. **响应解析**：正常响应能够取出文本；异常响应按规则失败，并且不重试。
5. **单轮和多轮**：`prompt` 与 `messages` 的角色、顺序和内容按预期传递。
6. **流式输出**：不纳入本次验收。

## 2. 测试范围

### 当前测试范围

- `chat()` 接口
- Prompt 输入校验
- 请求参数传递
- 重试机制
- 响应解析
- 单轮和多轮对话

### 未来扩展

- 流式输出等尚未实现的功能

### 不测试

- 图片、文档 API 调用
- DeepSeek 以外的其他模型适配

## 3. 优先级

- **P0**：输入校验、默认参数传递、只改写 `model`、重试与不重试、响应解析的主路径（含 `content` 为空字符串）、四条真实 API 冒烟。验收时必须全部通过。
- **P1**：调用时改写 `temperature`、`max_tokens`、`timeout`，以及多项组合改写；响应 `content` 只含空白。P0 通过后再做。

## 4. 风险与限制

1. **真实 API 费用**：真实 API 调用会产生 Token 消耗和费用，需要控制测试次数及测试数据规模。
2. **Mock 测试局限**：Mock 只能验证客户端自身的处理逻辑，不能完全验证服务端的实际执行情况。
3. **网络与服务限制**：网络不稳定、429 限流、账号额度不足等可能影响真实 API 测试结果。
4. **模型输出不确定性**：相同 Prompt 可能产生不同回答，真实 API 测试不宜对非确定性内容设置过于严格的固定文本断言。
5. **服务商模型变化**：模型升级、接口变更可能影响测试结果，需要关注服务商 API 变化。
6. **重试机制风险**：重试可能产生重复调用和额外 Token 消耗，需要关注重复执行、幂等性及费用风险。

## 5. 验收标准

### 进入

- 测试环境能够正常运行。
- 测试账号及 API 配置准备完成。
- 测试用例及测试数据准备完成。

### 退出

1. 当前测试范围内的核心用例全部执行。
2. P0 全部通过。
3. 无未解决的阻断性问题。
4. 失败用例均有分析记录。
5. 具有完整的测试执行结果和测试报告。

## 6. 交付排期

1. 五个模块的用例和脚本已经齐备。
2. 当前交付：P0 全部通过。
3. 随后交付：P1。
4. 本次不排：流式输出。
